# AAA URBAN — обновление сайта

Адаптивный сайт для Cloudflare Workers. Русская версия — `/`, казахская — `/kz`. Контакты пока оставлены прежними. В этой версии база D1 не требуется.

## Что изменено

- Первый экран: «Весь объект — под нашим контролем», сферы работы, WhatsApp и предложение.
- Управление, инженерия, безопасность и территория раскрываются во вкладках с фотографиями.
- Добавлены краткие преимущества, коммерческая недвижимость, задачи ОСИ и бесплатный аудит ЖК.
- Подготовлена фотогалерея настоящих сотрудников. Пока фото не добавлены, посетитель видит направления работы команды.
- Сохранены три корпоративных кейса с цветными логотипами и пометкой «Опыт группы». Добавление кейсов ЖК автоматически включает фильтр категорий.
- Крупные заголовки, курсивные акценты, плавное появление текста, вращающийся индикатор 360°. Анимации отключаются при настройке «Уменьшение движения» на устройстве.
- Форма подготавливает сообщение в WhatsApp; посетитель проверяет его и отправляет в чате.
- Настроены SSR, язык HTML, canonical, альтернативные языки, метаданные, Schema.org, robots.txt и sitemap.xml.
- Добавлены 8 отдельных SEO-страниц услуг на русском и 8 соответствующих страниц на казахском. Все страницы имеют собственный intent, H1, metadata, FAQ, Service schema и внутренние ссылки с главной.

В публичных текстах нет названий других направлений группы. Прежняя почта сохранена по заданию. Вымышленные сотрудники, кейсы ЖК и неподтверждённые результаты не добавлены.

## Где самостоятельно менять контакты

Откройте в GitHub **app → site-settings.ts → Edit**. Меняйте только значения в кавычках:

| Поле | Что указывать |
| --- | --- |
| `phoneDisplay` | Номер в удобном виде: `+7 701 220 01 12` |
| `phone` | Номер для звонка без пробелов: `+77012200112` |
| `whatsapp` | Номер продажника с кодом страны, без плюса: `77012200112` |
| `email` | Рабочая почта |
| `address.ru`, `address.kz` | Полный адрес на двух языках |
| `city`, `street` | Город и адрес для поисковых систем на двух языках |
| `siteUrl` | Основной адрес после подключения собственного домена |

Сохраните кнопкой **Commit changes**. При подключении GitHub к Cloudflare Builds новая публикация начнётся автоматически.

Переменная Cloudflare `NEXT_PUBLIC_SITE_URL` имеет приоритет над `siteUrl`. При смене домена обновите её или удалите, чтобы использовать значение из файла.

## Как добавить фотографии команды

1. Загрузите собственные фото в `public/team/`: WebP/JPEG, портрет 4:5, ширина от 800 px, около 150–300 КБ.
2. Откройте `app/portfolio.ts`.
3. Вместо пустого списка `teamMembers` внесите реальные данные. Пример — шаблон, замените все значения:

```ts
export const teamMembers: TeamMember[] = [
  {
    id: "employee-01",
    name: { ru: "Имя сотрудника", kz: "Қызметкердің аты" },
    role: { ru: "Должность", kz: "Лауазымы" },
    photo: "/team/employee-01.webp",
    position: "50% 30%",
    published: true,
  },
];
```

Для нескольких сотрудников повторите объект `{ ... }`, разделяя их запятыми. `published: false` скрывает карточку. `position` регулирует положение лица в кадре.

## Как добавить кейс ЖК

Загрузите согласованную фотографию в `public/cases/`. Добавьте запись в массив `caseStudies` файла `app/portfolio.ts`:

```ts
{
  id: "residential-01",
  category: "residential",
  title: { ru: "Название ЖК", kz: "Тұрғын үй кешенінің атауы" },
  scope: {
    ru: "Подтверждённый состав выполненных работ",
    kz: "Расталған жұмыстардың құрамы",
  },
  period: "Период работы",
  attribution: "urban",
  photo: "/cases/residential-01.webp",
  published: true,
},
```

Для опыта группы укажите `attribution: "group"`; для проекта AAA URBAN — `"urban"`. Поле `logo` необязательно. Не используйте иллюстративные фото как доказательство реального кейса. Первый опубликованный ЖК включает фильтры «Все объекты / Корпоративные / Жилые комплексы».

## Как обновить существующий GitHub и Cloudflare

1. Распакуйте архив. Откройте папку с `package.json`.
2. Замените файлы в существующем репозитории, сохраняя вложенные папки. Не загружайте ZIP как один файл. Сохраните собственные изменения, если редактировали проект после прежнего экспорта.
3. Обязательно загрузите **vendor/shadcn-tailwind-4.13.0.css**: именно эта папка отсутствовала в предыдущей неудачной сборке.
4. В `wrangler.jsonc` имя Worker — **aaaurban**, как в текущем адресе. Блок D1 убран.
5. В настройках сборки существующего Worker:

| Настройка | Значение |
| --- | --- |
| Production branch | Рабочая ветка, обычно `main` |
| Root directory | Корень репозитория с `package.json` |
| Build command | `npm run build` |
| Deploy command | `npx vinext deploy --skip-build` |
| Node.js | `24.19.0` или совместимая версия 22.13+ |
| NEXT_PUBLIC_SITE_URL | `https://aaaurbanver2.corparationsite.workers.dev` до подключения домена |

6. Сохраните изменения в GitHub. Дождитесь успешной сборки и публикации Cloudflare.
7. Откройте `/` и `/kz` с телефона. Проверьте меню, вкладки, типы объектов, основные кнопки и номер WhatsApp. Для проверки формы достаточно открыть подготовленное сообщение; отправлять тестовую заявку необязательно.

Архив содержит исходный код, а не выполненную публикацию. Доступ к вашему Cloudflare/GitHub для автоматической публикации в этой сессии отсутствует.

## Локальная проверка

```bash
npm ci
npm test
npx tsc --noEmit --incremental false
```

`npm test` собирает production Worker и проверяет ответы RU/KZ, SEO, изображения, внутренние ссылки, номера WhatsApp и отключённый старый API. Браузерные клики и визуальное отображение эта команда не проверяет.

Для разработки: `npm run dev`. Для публикации с авторизованного компьютера: `npx wrangler login`, затем `npm run deploy`.

## Заявки, аналитика и Битрикс

- **WhatsApp:** работает без базы. Пользователь отправляет сообщение сам. В базе сайта заявки не сохраняются.
- **Битрикс:** пока не подключён. Для отправки форм в CRM нужны серверная интеграция, права и данные от специалиста заказчика. Секретный webhook нельзя размещать в `site-settings.ts`, клиентском коде или публичном GitHub.
- **Старый `/api/inquiries`:** возвращает статус 410, ничего не сохраняет и не требует D1. Старые открытые вкладки не получат ложное подтверждение заявки.
- **Аналитика:** события `cta_click`, `whatsapp_click`, `phone_click`, `email_click`, `object_select`, `section_view`, `inquiry_prepared` подготовлены в `dataLayer`. Имя, телефон и комментарий туда не передаются. GTM/GA4 не активированы без идентификаторов заказчика. Открытие WhatsApp не равно отправке сообщения.
- **Search Console:** подтверждение домена выполняется в аккаунте владельца; оно не заменяется sitemap.

Файлы `db`, `drizzle`, `examples/d1` сохранены как неиспользуемые заготовки старого экспорта. Текущий сайт не обращается к базе; запускать миграции не нужно.

Не загружайте в GitHub `node_modules`, `dist`, `.wrangler`, локальные `.env` и секретные ключи. В этом архиве их нет.
